## 3. 결정 기록

### D1. `wireframe.md`를 덮어쓰지 않는다

요청 문구는 "wireframe.md으로 작성해서"였다. 문자 그대로 읽으면 그 파일에 쓰라는 뜻이 된다.

- 기각: `wireframe.md`에 설계서를 덮어쓴다. 6층 프레임을 설명하는 교재 원문이 사라진다.
- 채택: `wireframe-spec.md`를 새로 만든다. "wireframe.md**으로**" = "wireframe.md의 프레임을 써서"로 해석.

이 판단은 사용자에게 알리고 진행했다.

### D2. 뷰어를 `index.html`과 분리한다

- `index.html` = 구현물. 실제로 입력받고 검증하고 제출한다.
- `wireframe-spec.html` = 문서. 목업은 `pointer-events: none`으로 상호작용을 죽인 정적 재현이고, 상호작용은 핀과 필터에만 붙였다.

두 파일이 같은 화면을 그리지만 목적이 다르므로 합치지 않았다.

### D3. 목업을 좁게 다시 짜지 않고 원본 폭 유지 후 축소한다

좌측 컬럼은 약 600px인데 원본 카드는 1120px이다.

- 기각: 목업을 600px 폭으로 다시 마크업한다. 2열 그리드가 1열로 접혀 원본과 다른 화면이 된다. 설계서의 목업이 실제 화면과 다르면 문서로서 실격.
- 채택: 1120px 그대로 두고 `transform: scale(S)`로 축소. 핀만 `scale(1/S)`로 역보정해 배율과 무관하게 같은 크기로 읽히게 했다.

### D4. 핀 위치를 CSS 고정이 아니라 실측 배치한다

annotation 대상이 `h1`, `div`, 그리드 컨테이너, 인라인 텍스트로 제각각이라 CSS 한 벌로 일관 배치가 안 됐다.

- 채택: 각 요소에 `data-anno` 속성을 주고 `getBoundingClientRect()`로 목업 기준 상대좌표를 구해 절대 배치. 창 크기가 바뀌면 `resize`에서 재계산.
- 부작용: 요소가 붙어 있으면 핀이 겹친다. 아래 F2에서 실제로 터졌고, 요소별 오프셋(`dy`, `pinRight`)으로 해결했다.

렌더링은 전부 헤드리스 크롬 `--screenshot`으로 찍어 눈으로 대조했다.

### F1. `.grid-3`에 `display: grid` 누락

첫 렌더링에서 체크박스 3개(야외석 / 주차 / 인터넷)가 3열이 아니라 세로로 쌓였다. `.grid-3`를 `.grid`의 수정자로 설계해놓고 HTML에서는 `class="grid-3"`만 썼다. `display: grid`가 어디에도 걸리지 않았다.

`.grid-3`에 `display: grid`를 직접 넣어 해결.

### F2. 핀 겹침

뷰어 첫 렌더링에서 ⑭(상태 문구)가 예약 버튼 위에 얹혔다. 버튼과 문구가 가로로 나란해서 문구의 왼쪽 -44px이 버튼 영역이었다. ⑫(체크박스 그룹)는 ⑪(섹션 라벨)에 세로로 붙었다.

- ⑭ → `pinRight: true`로 요소 오른쪽 바깥에 배치
- ⑫ → `dy: 18`로 아래로 밀어 체크박스 카드 높이 안으로

수정 후 실측: 핀 14개 상호 겹침 0건.

### F3. `th` 대문자 변환

Deploy 표의 행 헤더가 `text-transform: uppercase`라 `file://`이 `FILE://`로 보였다. 해당 셀만 `text-transform: none`.

## 5. 도구 함정 하나

헤드리스 크롬 `--screenshot`은 **`window.scrollTo` 이후에도 스크롤 위치를 반영하지 않는다.** 하단 표를 찍으려고 스크롤 후 캡처했더니 빈 회색 화면만 나왔다.

페이지 쪽 문제인 줄 알고 디버그를 찍어보니 `TABLES_TOP_AFTER: 88.34` - DOM은 정상이었다. 캡처 도구 특성이었다.

우회: 상단 영역을 `display: none`으로 죽인 임시 사본을 만들어 찍었다. 다음에 긴 페이지 하단을 캡처할 일이 있으면 같은 방법을 쓴다.

## 6. 이 화면에서 6층 프레임이 실제로 걸린 지점

교재가 말한 것이 이 화면에 그대로 있었다.

**mutable과 append가 한 화면에 둘 다 있다.** select 5개(region, cuisine, price, people, time)는 새 값이 이전 값을 지우는 mutable이다. 체크박스 3개(prefs)는 동시에 고를 수 있어 이전 선택이 남아야 하는 append다. 구현에서 이 차이가 그대로 코드로 나타났다.

```js
formData[f.key] = f.el.value;                    // mutable: 덮어쓴다
formData.prefs.push(cb.value);                   // append: 쌓는다
```

**Deploy 층이 한 줄로 끝났다.** 이 화면은 fetch도 geolocation도 지도 SDK도 쓰지 않아서 `file://` 직접 열기로도 동작한다. 대신 서버 전송을 붙이는 순간 HTTPS와 CORS 도메인 등록이 필요해진다고 적어뒀다. 교재가 말한 "배포 당일에 발견"을 막는 칸이다.
