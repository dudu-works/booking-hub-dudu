# 오후 실습 공통 카드

오늘 다루는 것은 전부 **가상의 데이터**입니다. 실제 기관·실제 사람이 아닙니다.

## 오늘의 한 문장

**우리는 운영자이고, 이용자가 무엇을 찾는지 모릅니다.** 원본에는 분류 열이 없고 자유 문장만 있습니다. 그 문장에서 판단값을 뽑되, 무엇을 인정하고 무엇을 뺄지를 **정책으로 먼저 정한 다음** AI에게 분류를 시킵니다.

## 다섯 단계

### 1단계 - 원문 관찰 (타깃 비공개)

1. `data/raw.csv`를 **복사하지 말고 그대로 보존**합니다.
2. 열마다 무슨 유형인지 적습니다. 숫자인지, 정해진 몇 종류인지, 자유 문장인지.
3. 자유 문장 열에 **어떤 표현들이 실제로 있는지** 훑습니다. 20행 정도면 충분합니다.
4. 아직 필터 조건을 만들지 않습니다. 이용자가 누구인지 모르는 상태입니다.

### 2단계 - 판단 열 정의

원본 열 이름과 같은 것을 찾지 말고, **새로 만들 판단 열**을 정합니다.

- 값은 세 가지만 씁니다: `가능` / `불가` / `확인 필요`
- 애매한 것을 `가능`으로 올리지 않습니다. `확인 필요`가 정상적인 답입니다.

### 3단계 - 분류 정책 쓰기 (오늘의 핵심)

판단 열마다 아래 표를 채웁니다. **이걸 안 채우고 AI에게 시키면 매번 다른 답이 옵니다.**

| 판단 열 | 정책 문장 | 포함하는 표현 | 제외하는 표현 | 애매하면 |
|---|---|---|---|---|
| 예시 | 추가 비용이 0원인 것만 무료로 본다 | `수강료 없음`, `전액 무료` | `교재비 별도`, `재료비 실비` | 확인 필요 |

정책은 옳고 그름이 아니라 **설명 가능한가**로 판단합니다. 같은 데이터에 다른 정책을 걸면 결과 행수가 달라지는 것이 정상입니다.

### 4단계 - AI와 함께 분류

정책을 정한 뒤에 AI에게 넘깁니다. 세 가지를 지킵니다.

1. **id를 함께 보냅니다.** 판단할 열만 떼서 보내면 돌아온 값을 어느 행에 붙일지 알 수 없습니다.
2. **개수 유지를 문장으로 못 박습니다.** "빈 값도 한 건으로 세고 100줄을 유지하라"를 적지 않으면 빈 줄이 사라져 돌아옵니다.
3. **눈으로 세지 않고 수식으로 확인합니다.**

```
=COUNTA(결과id범위)                     -> 100이어야 합니다
=SUMPRODUCT(--(원본id범위<>결과id범위))   -> 0이어야 합니다
```

붙여넣기는 `선택하여 붙여넣기` -> `값만` -> `텍스트를 열로 분할` 순서입니다.

### 5단계 - 타깃 공개 후 비교

타깃 카드를 받으면 2·3단계에서 쓴 것과 비교합니다.

- 내가 상상한 이용자와 실제 이용자가 어떻게 달랐나
- 내 정책이 실제 이용자에게 맞았나, 너무 좁았나, 너무 넓었나
- 조건을 `AND`로 묶을지 `OR`로 묶을지는 **도메인이 정합니다**. 하나라도 되면 되는 것인지, 전부 갖춰야 하는 것인지.

## 완료 영수증

```
이름 / 원본 100행 / 판단 열 __개 / 내 정책 한 줄 / 타깃 공개 전 예상 이용자 / 공개 후 논리(AND·OR·혼합) / 결과 __행 / 확인 필요 __행 / 초기화 100행 O·X / 원본 무변경 O·X / 수정본 링크
```

`확인 필요`가 몇 행인지 반드시 적습니다. **0행이면 오히려 의심합니다** - 애매한 것을 다 밀어 넣었다는 뜻일 수 있습니다.
